# Moskow Event — учебная EMS

Корпоративный сайт и система управления мероприятиями по «Промт.txt». Русский интерфейс, Vue 3 Composition API, Pinia, Vue Router, Express 5, Mongoose, Socket.io, PDFKit, Chart.js. Фирменный SVG и палитра из задания. Разделы открываются отдельными страницами по URL: `/events`, `/calendar`, `/contacts`, `/account/tickets`, `/admin/events` и т. д.; меню не прокручивает один лендинг.

## Быстрый запуск

Нужен Node.js 22+ (обычная установка включает npm). Из папки проекта:

```sh
node start.mjs
```

Первый запуск устанавливает зависимости, если они отсутствуют. Интернет необходим для установки. Готовая сборка включена. Откройте **http://localhost:3001**. В Windows можно запустить **start.cmd**.

Без MongoDB включается подписанный в шапке файловый деморежим; изменения сохраняются в `backend/data/state.json`. Это полноценный локальный backend, а не данные только в браузере. Не запускайте два процесса с одним файлом.

Обычные команды:

```sh
npm install
npm run dev     # API :3001 + frontend :5173
npm run build
npm start       # собранный сайт и API на :3001
npm test        # отдельный тестовый сервер :3137, 28 проверок
npm run seed    # инициализация без удаления существующих данных
```

Если npm отсутствует в среде Codex, `node start.mjs` также умеет использовать поставляемый с Node runtime pnpm. Не открывайте `dist/index.html` двойным щелчком: приложению нужен API.

## Демоаккаунты

| Роль | Email | Пароль |
|---|---|---|
| Участник | guest@demo.local | MoscowDemo2026! |
| Администратор | admin@demo.local | MoscowDemo2026! |

Волонтёра и спикера можно зарегистрировать самостоятельно. Организатора, менеджера, координатора и бухгалтера назначает администратор в «Пользователи». Нельзя самостоятельно зарегистрировать администратора. Участнику не доступны управленческие API. Бухгалтерская роль выделена в модели; бухгалтер видит отчёты, сметы и документы.

В seed: 12 мероприятий (одно прошедшее), 5 спикеров, 3 площадки, 2 подрядчика, 10 клиентов, склад, три демонстрационных отчёта. У участника есть билет на прошедшее событие для скачивания сертификата. Рабочие тесты создают отдельное временное хранилище и не меняют вашу базу.

## Что работает

- Главная: смена трёх баннеров, ближайшие события, календарный блок, компания, форматы, кейсы, пример отзыва, отрасли клиентов, подписка, контакты.
- Каталог: поиск по названию/тегам/спикерам, тип/формат/город/дата, список, сетка, помесячный календарь, прошедшие и ближайшие.
- Страница события: программа, спикеры, площадка с картой Яндекса, регистрация, ограничение мест, защита от повторных билетов, избранное.
- JWT access 15 минут, вращаемый refresh в HttpOnly cookie на 7 дней, bcrypt; восстановление через SMTP или демоочередь; профиль и настройки.
- ЛК: история, QR-билеты, PDF-сертификаты после события, уведомления, локальное избранное, рекомендации ближайших событий, демонстрационные бонусы, голосование.
- Управление: CRUD мероприятий/площадок/подрядчиков/клиентов, программа/теги/спикеры, воронка клиентов и история контактов, бронирования с четырьмя статусами, входящие заявки и их статусы/бюджеты в кабинете заказчика, сметы с расчётом итога, учёт ссылок на документы, роли пользователей.
- Три отчёта: таблицы и Chart.js, Excel-экспорт. Отчёты используют примеры из задания, подписаны как демонстрационные и не пересчитываются из новых продаж.
- Волонтёрский чат: общий/личные каналы, WebSocket, файлы PNG/JPG/PDF/TXT до 500 КБ, закрепления, задачи с назначением и отметкой выполнения. Смена роли отключает активное подключение.
- Фирменный PDF с кириллицей, данными участника и события, настраиваемыми заголовком/подписью/нижней строкой.
- Внутренняя аналитика переходов, reCAPTCHA v3 при настройке, S3 для файлов чата при настройке, Nodemailer при настройке. Напоминания и уведомления о сертификатах проверяются раз в минуту работающим сервером.

## MongoDB и Docker

Скопируйте `.env.example` в `.env`, задайте `MONGO_URI`. В MongoDB сущности сохраняются отдельными коллекциями Mongoose, дополнительные данные — в State. Для разработки:

```sh
docker compose up --build
```

Откройте http://localhost:3001. Контейнеры MongoDB и приложения сохраняют данные в volumes. Docker запускает учебный режим с демоаккаунтами. Для промышленного окружения задайте `NODE_ENV=production`, `JWT_SECRET`, `RECAPTCHA_SECRET`, `ADMIN_EMAIL`, `ADMIN_PASSWORD` (от 14 символов), HTTPS и корректный `CLIENT_ORIGIN`. Демоучастник при первой production-инициализации не создаётся. Не переносите учебную базу с демопаролями в production.

Хранилище загружается в память одного процесса; горизонтальное масштабирование и транзакции нескольких реплик требуют переработки репозиториев. MongoDB/Docker в этой среде не запускались; проверен файловый backend.

## Интеграции и окружение

- `CLIENT_ORIGIN`: `http://localhost:5173` для разработки, `http://localhost:3001` для локальной сборки, реальный HTTPS-домен для облака.
- `JWT_SECRET`: случайный секрет; без него в development генерируется временный, поэтому перезапуск завершает сессии.
- `RECAPTCHA_SECRET` + `VITE_RECAPTCHA_SITE_KEY`: секрет сервера и публичный ключ; после изменения VITE-переменной пересоберите frontend. Production без серверного ключа отклоняет защищённые формы.
- `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM`, `PUBLIC_URL`: SMTP и адрес для восстановления. Без SMTP письма пишутся в локальную demo-outbox, а не отправляются. Сертификат скачивается в кабинете; прямое SMTP-уведомление после события включает PDF-вложение.
- `S3_ENDPOINT`, `S3_BUCKET`, `AWS_REGION`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`: S3-совместимое хранилище вложений. Без bucket файлы сохраняются локально; скачивание требует права доступа к чату/переписке.
- `PDF_FONT`: абсолютный путь к TTF с кириллицей. Windows использует Arial; Docker — DejaVu Sans. На других системах задайте переменную.
- Zoom, оплата, 1С, amoCRM, Битрикс24: явно обозначенные адаптеры-заглушки. Деньги не списываются, Zoom-встречи и CRM-контакты во внешних сервисах не создаются. Время допуска подключения проверяется сервером.
- Google Analytics / Яндекс.Метрика: внешние счётчики не активированы; используется собственный сбор событий. Карты и Google Fonts требуют интернет-соединения; для шрифта предусмотрен Arial fallback.

## Практические материалы и ограничения

Приоритет источников: `docs/requirements.txt` → присланные бриф, карточка компании, требования и классификатор. «отчеты.docx» и «Автоматизация.docx» описывают ремонт техники, поэтому их предметная область не переносилась в EMS. Папка C:\Claude и HTML-образец отсутствуют; по указанию пользователя использованы только вложения. Фотографий кейсов нет: изображения созданы CSS-геометрией; кейсы и отзыв явно демонстрационные.

В исходном примере сроки подтверждения дают среднее 18,7 ч с весами по количеству заявок, а не 17,7 ч. Для долей в seed использованы целые количества подтверждений. В интерфейсе приведены вычисленные итоги с пояснением.

Это работающая учебная реализация, не готовое промышленное развёртывание. Ограничения: нет облачной публикации, полноценного расчёта партнёрских вознаграждений и английской версии. Редактор текстовых публикаций и учёт партнёрских ссылок доступны организатору; кейсы наполнены демонстрационными материалами. Избранное хранится на устройстве. Рекомендации — ближайшие ещё не выбранные события; бонусы — демонстрационный расчёт. Публикация в облако и подключение реальных интеграций не выполнены.
